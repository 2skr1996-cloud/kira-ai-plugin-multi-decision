一个给 KiraAI 用的聊天插件：决定机器人在群里什么时候开口，以及每次开口带多少前面的聊天记录。

KiraAI 自带的判定是随机掷骰子，要么半天不回，要么逮着一句就回。这个插件把「回不回、等多久回、带多少上下文」全搬到网页上，一条条能调、能看、能复盘。

> [!TIP]
> 不用另外装东西。在 KiraAI 里把要用的模型设好，其余配置插件都接管了。

## 它解决什么问题

- 掷骰子太粗糙：要么不回、要么逮着一句就回。这里能按条数、概率、时段定，也能先让便宜模型看一眼。
- 上下文窗口看不懂也改不动：留多少、什么时候裁、裁哪段，都在设置页。
- 出了问题没法复盘：判定、请求、裁切都留快照，网页上能一条条点开。

> [!WARNING]
> **B3.1.5（Beta 测试版），可能有不少 BUG。**
>
> - 私聊、决策模式、JEV 决策都没经过充分测试，出问题别意外。
> - 让模型自己调用工具（查资料、取图片）的多轮流程，测试得还不够充分。
> - 遇到怪现象，先去首页按时间翻对应的回复记录或决策记录，多半能看出原因。
> - 窗口快照（每轮发给模型的完整内容存档）可能包含聊天内容、系统提示词等敏感信息；开 issue 或截图前请先脱敏。

## 功能清单

**判定**

| 项目 | 说明 |
| --- | --- |
| 计数 | 攒够 N 条消息回一次 |
| 概率 | 每条消息按百分比随机；开了节奏模式就按间隔排队，越等越容易中 |
| 时段 | 一天切 48 格，每格半小时一个概率；点段上的月亮，那段就是休息时段 |
| 动态调整 | 不用手填，按最近几天的数据自己调；得先开时段曲线。当前收益不高，以后可能重做 |
| 决策模式 | 另起一个模型读这一轮的消息判「回不回」，判回才跑完整一轮回复 |
| JEV 决策 | 交给接入的专用判断模型（如 Jev）判回不回，只判不写回复 |

**触发与时机**

| 项目 | 说明 |
| --- | --- |
| 触发必回 | 艾特、名字、外号三路，各有「触发」和「必回」两个开关（艾特触发 / 艾特必回） |
| 休息时段 | 单独一套概率；睡着被叫时理不理另有两个开关 |
| 防抖合并 | 同一个人连发几句先攒着，合成一条再回（连发合并） |
| 抖动等待 | 命中后等固定秒数再发；期间又攒够一次就再叠一档 |
| 短语过滤 | 整条等于黑名单短语的不算一次触发（短语黑名单） |
| 用户黑名单 | 拉黑的人不发给模型，窗口里还能看到；可按群单独解除 |
| 冷场补位 | 安静太久补一次；休息时段另有一套（静默兜底） |
| 静默过滤 | 补之前先看决策完之后的头几条，只有链接、短句、图、表情包、文件视频就不补；每一项能单独设管前几条 |

**配额与覆盖**

| 项目 | 说明 |
| --- | --- |
| 配额 | 每小时 / 每天两档上限，私聊豁免，恢复即触发 |
| 单群覆盖 | 每个群一套独立设置，没单独设的跟全局走 |

**上下文**

| 项目 | 说明 |
| --- | --- |
| 上下文窗口 | 自己存一份聊天历史，不跟 KiraAI 自带的记忆混在一起 |
| 上下文裁切 | 攒到设定条数就裁一次，只留最近几条；裁的时候避开工具调用 |
| 历史图片 | 最近 128 张原图带给模型，可改；动图三档：首帧 / 九帧拼图 / 原样 |
| 转发消息 | 合并转发默认只挂前几张图，模型需要时自己再取；动图默认不发 |
| 文件不进上下文 | 纯文件消息整条不进窗口，带文字的文件消息只留文字 |
| 引用编号 | 引用里的每张图按顺序编号，模型说「第二张」不会对错图 |
| 图片缓存 | 聊天里的图存一份本地副本，框架清掉原图后照样能看 |
| 图片压缩 | 框架那四项压缩参数也能在这里改；长截图会先自动缩小再发 |
| 窗口快照 | 每轮请求、每次裁切都存一份带编号的快照，走势图上点柱子能翻回去 |

**工具**

模型自己会调的两个工具，用来把已经不在窗口里的东西取回来。在「提示词」页的「工具说明」里勾上才会挂给模型，决策和回复各有一份。

| 工具 | 什么时候用 | 取回什么 |
| --- | --- | --- |
| `view_forward` 查看转发 | 合并转发只挂了前几张图，模型想看全部 | 这条转发里的所有图 |
| `view_quote` 查看引用 | 被引用的那条已经裁出窗口，只剩一行引用 | 原消息的正文和里面的图 |

**提示词**

| 项目 | 说明 |
| --- | --- |
| 三套提示词 | 决策 / JEV / 回复各一套，都能改 |
| 模块化 | 拆成模块上下排，右边实时预览拼好的结果 |
| 试跑 | 决策、JEV、回复三页都能用当前会话的记录试跑一次，只显示结果，不写记录、不发言 |

**记录与统计**

| 项目 | 说明 |
| --- | --- |
| 实时窗口 | 这一轮实际发出去的消息，按段拆开看 |
| 回复记录 | 每轮回复的渠道、模型、真正发出去的文字 |
| 决策记录 | 每次判定的理由、结论、耗时 |
| 走势图 | 每根柱子是一份窗口快照，点开能翻回那一刻 |
| 引用跳转 | 点一下引用块就跳到被引用的那条消息；不在当前窗口里，会自动打开它所在的那一轮快照 |
| 缓存记录 | 各类缓存占了多少、上限多少，可以按类别清；用量账本单独一行、永久保存 |
| API 价目 | 填模型单价，页面才算得出花了多少钱；配柱图和双环饼图看用量与花费 |

## 数据放在哪

全部落在 KiraAI 安装目录下的 `data/plugin_data/kira-ai-plugin-multi-decision/`：

- `requests/`：窗口快照（每轮实际发出的 system 与本轮消息，裁切那一刻另存一份），排查问题主要看这里。
- `windows/`：裁切事件索引，记着哪一轮裁了多少条。
- `decisions/`：判定日志，一天一个文件。
- `media_cache/`：图片缓存本体。
- `stats/`：会话统计与用量。
- 还有一些状态文件（窗口状态、单群覆盖、价目、提示词布局、中期摘要、重试记录、转发图片索引等），一般不用管。

删插件目录不会删这些；要清掉请在「缓存记录」页按类别清，或手动删 `plugin_data` 下对应目录。窗口快照和图片缓存可能占用磁盘空间，也可能包含聊天内容、提示词或其他敏感信息。

## 安装

> [!IMPORTANT]
> 先在 KiraAI 的模型设置里配好一个聊天模型（回复用）；想用决策模式 / JEV 再各配一个。没配模型插件不会说话。

1. 从 [Releases](https://github.com/2skr1996-cloud/kira-ai-plugin-multi-decision/releases) 下载最新的 zip，解压。
2. 把整个 `kira-ai-plugin-multi-decision` 文件夹放到 KiraAI 安装目录的 `data/plugins/` 下，不要多套一层。
3. 重启 KiraAI（或在插件列表里刷新），在插件列表里启用「多样决策」。启用即接管内置的 default-chat：原来那个掷骰子判定不再生效。
4. 打开插件页面，点顶部「设置」按需要改。默认值就是能直接跑的一套；模型没配时「设置」按钮会亮红点，点进去一路指到该补的那一项。
5. 想换回原来的样子：把插件首页顶部的开关关掉，或停用本插件，default-chat 会自动恢复。
6. 升级：直接覆盖插件目录，`plugin_data` 里的数据不动。

## 兼容性

- KiraAI 3.0.0 以上；JEV 决策接 KiraAI 里的模型要 3.1.1 以上，走自己填的第三方接口不受这条限制。
- Python 3.10 以上（KiraAI 自带运行环境的话不用管）。
- 只测过 DeepSeek 系和少数 OpenAI 兼容接口，别家的模型行为可能不一样。
