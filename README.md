一个给 KiraAI 用的聊天插件，接管群聊的触发判定与上下文窗口。

- 回不回、等多久回、上下文留多少，都在设置页上调，不用改代码。
- 每次判定、每次请求、每轮裁切都留快照，出问题能一条条点开看。
- 代码主要由 DeepSeek、GPT 辅助完成，作者是使用者不是专业开发者。

> [!TIP]
> 没有第三方依赖，装完就能用。只要在 KiraAI 里把要用的模型设好，其余配置插件都接管了。

## 它解决什么问题

- 默认掷骰子太粗糙，要么不回、要么逮着一句就回。这里能按条数、概率、时段定，也能先让便宜模型看一眼。
- 上下文窗口看不懂也改不动。留多少、什么时候裁、裁哪段，都在设置页。
- 出了问题没法复盘。判定、请求、裁切都留快照，网页上能一条条点开。

> [!WARNING]
> **B3.1.2（Beta 测试版），可能有不少 BUG。**
>
> - 私聊场景、以及 decision 决策模式（JEV）没有经过充分测试，出问题别意外。
> - 工具多轮调用可能还不够稳，这块测试得不够充分。
> - 遇到怪现象，先去首页按时间翻对应的回复记录或决策记录，多半能看出原因。
> - 窗口快照可能包含聊天内容、系统提示词或其他敏感信息；提交 issue 或截图前请先脱敏。
> - 欢迎开 issue，附上窗口快照里能说明问题的那一段（记得自己先抹掉隐私）。

## 功能清单

**判定**

| | 项目 | 说明 |
| --- | --- | --- |
| ✅ | 计数 | 攒够 N 条消息回一次 |
| ✅ | 概率 | 每条消息按百分比随机；开了节奏模式就按间隔排队，越等越容易中 |
| ✅ | 时段 | 一天切 48 格，每格半小时一个概率；点段上的月亮，那段就是休息时段 |
| ✅ | 动态调整 | 不用手填，按最近几天的数据自己调每段概率；得先开时段曲线。当前收益不高，以后可能重做 |
| ✅ | 决策模式 | 另起一个模型读这一轮的消息判「回不回」，判回才跑完整一轮回复 |
| ✅ | JEV 决策 | 交给接入的专用判断模型判回不回，只判不写回复 |

**触发与时机**

| | 项目 | 说明 |
| --- | --- | --- |
| ✅ | 触发必回 | 艾特 / 名字 / 外号三路，各有「算触发」「直接回」两个开关 |
| ✅ | 休息时段 | 单独一套概率；睡着被叫时理不理另有两个开关 |
| ✅ | 防抖合并 | 同一个人连发几句先攒着，合成一条再回 |
| ✅ | 抖动等待 | 命中后按固定秒数等再发；这期间又攒够一次触发就再叠一档，最多叠到上限 |
| ✅ | 短语过滤 | 整条等于黑名单短语的不算一次触发 |
| ✅ | 用户黑名单 | 拉黑的人，消息不进请求上下文，窗口里照常显示、默认折叠；名单全局生效，单个群可以自己解除 |
| ✅ | 冷场补位 | 安静太久补一次；休息时段另有一套 |

**配额与覆盖**

| | 项目 | 说明 |
| --- | --- | --- |
| ✅ | 配额 | 每小时 / 每天两档上限，私聊豁免，恢复即触发 |
| ✅ | 单群覆盖 | 每个群一套独立设置，没单独设的跟全局走 |

**上下文**

| | 项目 | 说明 |
| --- | --- | --- |
| ✅ | 上下文窗口 | 自己存一份聊天历史，不跟框架的记忆混在一起 |
| ✅ | 上下文裁切 | 攒够条数裁一次，裁完只留最近几条；不是发请求前顺手裁的时候，还要再多攒一点才动刀；切点避开工具调用，不会把一次调用和结果拆开 |
| ✅ | 历史图片 | 最近 N 张原图带给模型；动图三档：只发首帧 / 九帧拼图 / 原样发 |
| ✅ | 转发消息 | 合并转发默认只挂前几张图，模型需要时自己调工具取回完整内容；动图默认不发 |
| ✅ | 图片缓存 | 聊天里的图存一份本地副本，框架清掉原图后窗口里照样能看 |
| ✅ | 窗口快照 | 每轮请求、每次裁切都存一份带编号的快照，走势图上点柱子就能翻回去看 |

**回复**

| | 项目 | 说明 |
| --- | --- | --- |
| ✅ | 回复模型 | 可以单独指定，不填就跟框架默认走 |
| ✅ | 备用模型 | 主模型连错 2 次自动切过去，过一会儿再切回来；不想要就把「连续失败切换」关掉 |
| ✅ | 工具调用 | 回复和决策都能调工具，最多几轮、一轮几个、单个等多久、结果留多长都能设 |
| ✅ | 回复看图 | 回复模型也看一眼历史与本轮消息里的图片；关掉只发文字 |
| ✅ | 自动重试 | 出错自动重试几次，请求卡住超时也走重试；另有两个默认关闭的取舍开关：「处理排队消息」让重试带上等待期间攒的新消息，「超时不重试」让超时直接放弃这一轮 |

**提示词**

| | 项目 | 说明 |
| --- | --- | --- |
| ✅ | 三套提示词 | 决策 / JEV / 回复各一套，都能改 |
| ✅ | 模块化 | 拆成模块上下排，右边实时预览拼好的结果 |
| ✅ | 试跑 | 决策、JEV、回复三页都能用当前会话的记录试跑一次，只显示结果，不写记录、不发言 |

**记录与统计**

| | 项目 | 说明 |
| --- | --- | --- |
| ✅ | 实时窗口 | 这一轮实际发出去的消息，按段拆开看 |
| ✅ | 回复记录 | 每轮回复的渠道、模型、真正发出去的文字 |
| ✅ | 决策记录 | 每次判定的理由、结论、耗时 |
| ✅ | 走势图 | 每根柱子是一份窗口快照，点开能翻回那一刻 |
| ✅ | 缓存记录 | 各类缓存占了多少、上限多少，可以按类别清 |
| ✅ | API 价目 | 填模型单价，页面才算得出花了多少钱 |

## 数据放在哪

全部落在 `data/plugin_data/kira-ai-plugin-multi-decision/`：

- `requests/`：窗口快照（每轮实际发出的 system 与本轮消息，裁切那一刻另存一份），排查问题主要看这里。
- `windows/`：裁切事件索引，记着哪一轮裁了多少条。
- `decisions/`：判定日志，一天一个文件。
- `media_cache/`：图片缓存本体。
- `stats/`：会话统计与用量。
- 其余 `*.json`：窗口状态、单群覆盖、价目、提示词布局、中期摘要、重试记录、转发图片索引等。

删插件目录不会删这些；要清掉请在「缓存记录」页按类别清，或手动删 `plugin_data` 下对应目录。窗口快照和图片缓存可能占用磁盘空间，也可能包含聊天内容、提示词或其他敏感信息。

## 安装

1. 把整个文件夹放进 KiraAI 的 `data/plugins/` 下，目录名保持 `kira-ai-plugin-multi-decision`。
2. 在 KiraAI 的插件页启用「多样决策」。启用即接管内置的 default-chat：原来那个掷骰子判定不再生效。
3. 打开插件页面，按需要改设置。默认值就是能直接跑的一套。
4. 想换回原来的样子：把「基础设置」的总开关关掉，或停用本插件，default-chat 会被自动放开。升级就直接覆盖插件目录，plugin_data 里的数据不动。

## 兼容性

- KiraAI 3.0.0 以上；JEV 决策接宿主里的模型要 3.1.1 以上，走自己填的第三方接口不受这条限制。
- Python 3.11 以上。
- 只测过 DeepSeek 系和少数 OpenAI 兼容接口，别家的模型行为可能不一样。
