# 默认设置

插件自己的设置项一共 97 项，键名与出厂默认值如下。绝大多数能在插件的设置页里直接改；设置页没放出来的项，可以改 data/config/plugins/kira-ai-plugin-multi-decision.json（保存后热重载）。

| 键 | 名称 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | 启用插件 | 开 | 总开关。关闭后插件完全静默。 |
| `decision_enabled` | 接管默认聊天 | 开 | 接管并停用内置 default-chat。 |
| `trigger_mode` | 触发模式 | count | count 攒够条数；probability 按概率；adaptive 按曲线每段自动调概率。 |
| `trigger_threshold` | 计数触发 | 5 | 每 N 条回一次 |
| `trigger_probability` | 触发概率 | 20 | 按概率回 |
| `prob_pseudo` | 节奏模式 | 关 | 开 = 按节奏排队，越等越容易中；关 = 每条单独掷骰。 |
| `advanced_enabled` | 开启进阶模式 | 关 | 使用快速模型进行决策 |
| `reply_seg_overrides` | 回复提示词分段改写 | （空） | 设置页「回复提示词」左栏改过的段，JSON。留空 = 全部用框架原文。 |
| `decision_tools` | 决策可用工具 | （空） | 勾选后写进决策提示词，也作为原生工具一起发。 |
| `decision_model` | 决策模型 | （空） | 留空 = 用框架的快速模型。 |
| `decision_fallback_model` | 备用模型 | （空） | 主模型连续失败后切它；留空 = 不切。 |
| `decision_see_images` | 决策看图 | 开 | 决策模型也看一眼这一轮消息里的图片。它本身得是能看图的模型；万一上游不认图，会自动退回纯文字再判一次。 |
| `decision_fail_action` | 决策失败时 | allow | allow = 照常回复，block = 这轮不回。 |
| `decision_tool_loop` 等六项 | 决策的次数 / 时间设置 | 同回复 | 决策的最大代理循环次数、单轮工具调用上限、工具调用超时、工具输出上限、连续失败切换、切回主模型等待各有一套 `decision_*` 键，默认值与回复一致（5 / 5 / 180 / 10000 / 开 / 300），两边可各自调整。 |
| `reply_model` | 回复模型 | （空） | 真正写回复的那个模型。留空 = 用框架的默认模型。 |
| `reply_fallback_model` | 回复备用模型 | （空） | 主模型连续失败到「连续失败切换」那个次数才切它；留空 = 不切。 |
| `reply_fail_switch` | 回复连续失败切换 | 开 | 开＝主模型连错 2 次就切备用；关＝一直用主模型。 |
| `reply_fallback_cooldown` | 回复切回主模型等待 | 300 | 用备用模型撑过这段时间，再试回主模型。 |
| `reply_see_images` | 回复看图 | 开 | 回复模型也看一眼历史与本轮消息里的图片。关掉后只发文字，图片位置留 [图片] 占位。 |
| `jev_enabled` | JEV 决策 | 关 | 交给接入的专用决策模型（如 Jev）判回不回，不让它写回复。开了会自动关掉「决策模式」，两套配置各自保留，来回切不用重填。需要 KiraAI 3.1.1 及以上。 |
| `jev_model` | JEV 模型 | （空） | 只列启用提供商里的 decision 类模型。框架没有「默认 decision 模型」，这一项必须自己选。 |
| `jev_fallback_model` | JEV 备用模型 | （空） | 主模型连续失败到「连续失败切换」那个次数才切它，同样必须是 decision 类；留空 = 不切。 |
| `jev_fail_switch` | JEV 连续失败切换 | 开 | 开＝主模型连错 2 次就切备用；关＝一直用主模型。 |
| `jev_fallback_cooldown` | JEV 切回主模型等待 | 300 | 切到备用后过多少秒再试主模型。 |
| `jev_lower` | 不确定下限 | 25 | 回复概率低于这个百分比 = 不回复。设置页跟上限并成一行，用下拉选（0-100，步长 5）。 |
| `jev_upper` | 不确定上限 | 75 | 高于这个百分比 = 回复；落在上下限之间（含两端）算不确定，交给「不确定时」。设置页跟下限并成一行，用下拉选。 |
| `jev_action` | 不确定时 | no_reply | no_reply = 不回复，reply = 回复，decision = 转交一次普通决策（用「决策提示词」那一页的配置）。 |
| `jev_persona` | JEV 人格 | （空） | 留空跟随决策那一套的人格；判断提示词里提到的人设从这份来。 |
| `jev_backend` | JEV 走哪条路 | framework | 设置页已经没有这个选择：JEV 模型下拉里选宿主模型就走宿主，选「自定义 N」就走第 N 页。这个键只在老配置（没有 `jev_apis`、模型键为空）里兜底，`custom` 表示仍按第 1 页那份接口走。 |
| `jev_apis` | 自定义接口多页 | （空） | JSON 字符串，每项只存 `id` / `protocol` / `base` / `model`，最多 12 页；设置页右侧的 1…N 页签就是在改它。为空时用 `jev_api_base` / `jev_api_protocol` / `jev_api_model` 合成第 1 页。密钥不在这里，按页存在 `jev_secret.json` 的 `items[id]`。可单群覆盖。 |
| `jev_api_base` | 自定义接口地址（第 1 页 / 老配置） | （空） | 只填到站点的 api 前缀，插件按协议自己补后面的路径。必须 https，不能带账号密码、查询参数，不能指向本机或内网；填了非法地址会回落到 `https://api.typesafe.ai`。现在每页地址存在 `jev_apis`，这个键只在该键为空时作为第 1 页的来源。可单群覆盖。 |
| `jev_api_protocol` | 自定义接口协议（第 1 页 / 老配置） | systemone | systemone = 官方 Jev 那套，打 `/v1/systemone`，回的是一道 noul 题的概率；openai = OpenAI 兼容网关，打 `/chat/completions`，让普通模型按 JSON 回一个回复概率。阿里百炼、OpenRouter 这类只有 OpenAI 兼容，选 systemone 会打不通。新页默认 systemone，每页协议存在 `jev_apis`；这个键只在该键为空时作第 1 页来源。可单群覆盖。 |
| `jev_api_model` | 自定义接口模型名（第 1 页 / 老配置） | jev-latest | 第三方接口要求的 `model` 字段。SystemOne 走官方接口时是固定名字，阿里百炼为 `decision-model-preview`、TypeSafe 为 `jev-latest`，设置页「获取」会按地址给内置候选；OpenAI 兼容网关要填它清单里真实存在的模型名，「获取」从 `/models` 拉，拉不到也能手填。现在每页模型名存在 `jev_apis`，这个键只在该键为空时作第 1 页来源。可单群覆盖。 |
| （不进配置） | 自定义接口密钥 | （空） | 密钥不写在插件配置里，单独存插件数据目录下的 `jev_secret.json`（权限 0600），设置页只显示打码后的尾巴四位。存/清都走设置页那两个按钮，不随「保存设置」走，也不进单群覆盖。 |
| （无独立键） | JEV 的容错 | 同决策 | JEV 的重试次数、重试间隔、单次超时与失败动作都直接读基础设置页的 `retry_max` / `retry_delay` / `watchdog_seconds` 和 `decision_fail_action`；连续失败切换与切回主模型等待用自己的 `jev_fail_switch` / `jev_fallback_cooldown`。网络失败不会当成 0% 或 50%。 |
| `jev_prompt` | JEV 判断提示词 | （内置四条要点） | 平时在「提示词」页的「JEV 提示词」里改，正文与模块化布局一起存；直接手改配置文件时对应这个键，不进单群覆盖。 |
| `adaptive_step` | 每轮最多调几个点 | 2 | 每轮最多挪几个百分点。 |
| `adaptive_tune_minutes` | 调参间隔 | 10 | 隔多久重新算一次这段该用多少概率。越小跟得越快，也越容易被一天的波动带偏。 |
| `adaptive_rhythm_sigma` | 节奏松紧 | 65 | 回消息的节奏要多不固定：0 = 每隔固定条数回（像按时刻表），65 = 正常，偶尔早、最晚等 1.5 倍，120 = 很随意，最晚等 2 倍。只改手感，平均多久回一次不变。 |
| `stats_window_days` | 数据使用 | 7 | 每段平均按最近几天算，最少 7 天。 |
| `adaptive_weekday_bucket` | 使用星期数据 | 关 | 按同一个星期几比；不足 4 周退回最近 7 天。 |
| `bands_enabled` | 启用时段曲线 | 关 | 开着就按当前时段的概率决定回不回，普通模式那列变灰。 |
| `time_bands` | 时段曲线 | [{"s": 0, "e": 24, "v": 20}, {"s": 24, "e": 46, "v": 8}, {"s": 46, "e": 48, "v": 20}] | 一天切 48 格（每格半小时），每段一个概率；点段右上角的月亮，那段就是休息时段。 |
| `nicknames` | 机器人外号 | （空） | 群友叫 bot 的其它称呼，可加多条。 |
| `nickname_wake` | 外号触发唤醒 | 开 | 开启后喊外号直接进判断，不看计数。 |
| `name_wake` | 昵称触发唤醒 | 开 | 开启后喊机器人名字直接进判断，不看计数。 |
| `mention_always_reply` | 艾特必回 | 关 | 被 @ 时跳过模型判断直接回（开启进阶模式后与「艾特触发」的区别才看得出来）。 |
| `mention_trigger` | 艾特触发 | 开 | 被 @ 时直接算一次触发，不攒条数。 |
| `nickname_wake_always_reply` | 外号必回 | 关 | 被喊外号时跳过模型判断直接回。 |
| `name_wake_always_reply` | 昵称必回 | 关 | 被喊名字时跳过模型判断直接回。 |
| `rest_wake_trigger` | 休息时段·触发 | 关 | 休息时段里被艾特 / 喊外号 / 喊名字，还算一次触发。关掉＝睡觉时被叫也不理。 |
| `rest_wake_always` | 休息时段·必回 | 关 | 休息时段里被叫到时，上面那几个「必回」照样生效。默认关＝睡觉时必回也不叫醒。 |
| `jitter_enabled` | 抖动 | 关 | 新消息先等几秒，把这几秒的话攒一起。 |
| `jitter_seconds` | 抖动等待秒数 | 7 | 固定等这么多秒再动。这期间又攒够一次触发，就再叠一档（7 → 14 → 21），最多叠到下面「防抖上限轮次」那么多档——群里一直有人说话时，这一轮最多等这么久。 |
| `jitter_max_rounds` | 防抖上限轮次 | 3 | 最多叠几次；3 就是最多 7+7+7 秒，到顶不再拖。 |

| `burst_merge_enabled` | 连发合并 | 关 | 同一个人连着发好几条时只算一条消息。 |
| `burst_merge_seconds` | 连发合并秒数 | 15 | 这段时间内同一人的连发只算 1 条消息。 |
| `phrase_filter_enabled` | 短语黑名单 | 开 | 命中的纯文字不参与触发判定，消息本身仍留在上下文里。 |
